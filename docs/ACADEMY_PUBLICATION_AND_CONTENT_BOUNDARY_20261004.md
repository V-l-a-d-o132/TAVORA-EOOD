## Точният ред в Readdy

Официалната документация описва ръчен, а не автоматичен синхрон:
[GitHub integration](https://docs.readdy.ai/integrations/github).

1. В проекта на **imashnujnoto.com** отвори GitHub панела от `Connects` или
   GitHub иконата. Провери, че сочи към `V-l-a-d-o132/TAVORA-EOOD`.
2. Избери **Pull**. Това взема `main` и създава нова версия в Readdy.
   В историята има запис за repository URL и commit SHA; сравни SHA с
   действителния актуален `main`, не с по-стара бележка в този документ.
3. Прегледай именно създадената версия. Провери публичната видео страница и
   `/academy-labs/perfect-video/start`.
4. Публикувай тази версия чрез **Update** в настройките за вече свързания
   домейн. [React publishing](https://docs.readdy.ai/features/publish-react-v2)
   посочва, че нова версия се публикува отделно и не изисква нов DNS setup.
5. Провери реално зареждания сайт с командата по-долу. Запази резултата,
   вместо да приемаш успешния Pull или Update за доказателство за deployment.

**Push е обратната посока:** избраната Readdy версия заменя съдържанието на
GitHub `main`. За този release е нужен Pull. Не прекъсвай връзката с GitHub:
според документацията повторното свързване създава друго хранилище.

## Доказателство за публикуван frontend

`npm run build` генерира `out/academy-build.json`. Файлът съдържа само
отпечатък на frontend източниците, налична Git ревизия, време на build и
отпечатъци на входните и всички отделно зареждани JavaScript файлове. Няма .env стойности, учебни ключове,
студентски данни или Supabase архиви. Git ревизията може да липсва при Readdy
export; точният отпечатък на източниците остава основната сверка.

От чисто работно копие на проверения release:

```sh
npm run build
npm run verify:academy-deployment -- https://imashnujnoto.com out/academy-build.json
```

Проверката изисква еднакви frontend източници, HTML който зарежда обявения
entry, и действително сервирани JavaScript bytes със същия отпечатък,
включително отделно зарежданата публична курсова страница. HTML fallback,
липсващ manifest, стар код и смесена публикация са неуспех, не „готово“.
Не използва студентски профил и не проверява сама учебното качество или
достъпа. Ако Readdy промени конфигурацията или пропусне Vite plugin, липсващ
или различен отпечатък остава непотвърдена публикация и се разследва.

## Предотвратяване на ново изнасяне на ключове

CI проверява новите и изменените файлове в `src`, `public`, `supabase` и
`scripts` за разпознаваеми литерални grading mappings. Показва само файловите
пътища, никога отговорите. Непроменените стари миграции се запазват.

```sh
npm run check:academy-distribution -- origin/main
```

Проверката е ограничен защитен филтър: не открива всяка форма на кодирано,
косвено или подразбирано означаване на верен отговор. Новите реални mappings
остават в защитено server storage; не се комитват като авторски данни,
миграционни константи или редакционни exports. Синтетичните test fixtures са
отделени и Vite отказва включване на tests, releases, migrations и baseline
в runtime chunks. Това допълва, а не заменя сървърните права и RLS.

## Оставащо решение за старите публични ключове

Новият CI филтър **не премахва старото изтичане**. Препоръката е
`TAVORA-EOOD` да стане private, със запазен достъп за собственика, Codex и
Readdy GitHub App. Readdy официално създава private repositories, но достъпът
на текущите приложения трябва да се потвърди след промяната.

Преди промяна на видимостта провери GitHub Pages, публични forks и необходимите
collaborators/apps. GitHub предупреждава, че публичните forks остават
публични, а някои функции зависят от плана:
[Repository visibility](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility).

Private ограничава бъдещия достъп до основното хранилище; не изтрива изтеглени
копия или чужди forks и не прави старите въпроси тайни със задна дата.
Историята не се пренаписва, студентски записи не се изтриват, старите оценки
не се преизчисляват. Ако хранилището трябва да остане public, нужен е отделен
план за private curriculum distribution и нови изпитни варианти с миграция
на съвместимостта; проста промяна на option IDs не решава изтичането.

Промяната на видимостта и реалният Pull/Update не са извършени от този commit.
В наличните connector инструменти няма Readdy operation или GitHub операция
за промяна на видимостта.
